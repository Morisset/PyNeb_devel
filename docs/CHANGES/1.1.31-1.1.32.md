# Changes from 1.1.31 to 1.1.32

## Library bugs fixed

* `_CollDataStout` crashed with `ValueError: setting an array element with a sequence` on Stout
  collision files holding more than one `TEMP` block (`pynebcore.py`). When several blocks are
  present, the per-block level lists have different lengths, so the number of levels cannot be
  taken over them at once; it is now the maximum upper level accumulated across the blocks, which
  the reader already computes. This hit e.g. `pn.Atom('O', 3)` on the Cloudy c25.00 Stout `o_3`
  data (two blocks: 590 levels on a 10-point temperature grid, and levels 1-5 on a 19-point one),
  both with and without an explicit `NLevels`.

## Test suite

* `test_stout.py` grew two tests covering multi-`TEMP`-block Stout files, backed by a new
  `tests/STOUT/ne/ne_3` fixture (Cloudy c25.00 Ne III truncated to 5 levels, keeping its two
  blocks: levels 1-3 on a 27-point temperature grid, levels 1-5 on a 10-point one). They check
  the number of levels resolved across blocks, that each transition is interpolated on the grid
  of its own block, and that an explicit `NLevels` truncates or caps instead of raising.
